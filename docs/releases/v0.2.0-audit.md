# STRIX v0.2.0 — Release-Readiness Audit

Date: 2026-11-22 · Branch: `STRIX` (not merged to `main`) · Auditor: independent pass over the completed MVP

**Verdict: READY for release as a local MVP**, subject to the documented known
limitations below. No release-blocking defects found. One soundness hardening and
two fixes were applied during the audit (see CHANGELOG).

## 1. Change scope (`main..STRIX`)

171 files changed, +27,523 / −14. Net-new subsystems: `src/strix/agent/` (agent,
verifier, calculators, connectors, tools, orchestration, persistence, replay),
`src/strix/webapi/` (FastAPI), `web/` (React UI), and `tests/agent/` (+127 tests).
Pre-existing modules (pipeline, verification, market, corpus, engineering) are

## 2. Verifier-bypass analysis — PASS

The language model cannot assign or override a verdict, by construction:

- A `ClaimVerification` carrying a status is constructed in exactly **one** place:
  `verifier.py` `_verdict()`. Everywhere else (`orchestrator`, `persistence`,
  `response_validator`) `AgentVerificationStatus.VERIFIED` appears only in read
  comparisons (`is` / `is not`), never assignments.
- `submit_claim` builds `AgentClaim` with no `verification` argument → the
  default `ClaimVerification()` = `PENDING`. There is no `model_copy`,
  `verification=`, or status mutation path outside the verifier.
- The model cannot fabricate observation values: series are created only by data-
  tool handlers from preserved connector bytes; `calculate` and `submit_claim`
  can only *reference* existing series by id. The verifier recomputes from those
  preserved values.
- The orchestrator **discards the model's final prose** (`if not tool_calls:
  return None`); the answer is assembled deterministically from verified claims.
- `response_validator` fails closed: a claim in `verified_claims` must have status
  VERIFIED, resolvable citations, and (if quantitative) an independent
  recomputation, or the whole answer is withheld.
- API/synthesis layer: the web API serializes the already-verified answer and
  reloads persisted runs read-only; it never derives verdicts.

Tests: `tests/agent/test_verifier.py` (13) + `test_orchestrator.py` prove a wrong
claimed value is CONTRADICTED and that prompt-injection text in an excerpt cannot
grant numeric verification.

## 3. Integrity / calc / timestamps / citations / budgets / replay — PASS

- **Evidence integrity:** `content_hash = SHA-256(raw)`; evidence id derived from
  hash+url+anchor (dedup). Persistence re-verifies every preserved raw artifact's
  hash on write (`RunStore._preserve_raw_files`). A hash asserts integrity, not
  truth — stated in the inspector and docs.
- **Calculation correctness:** exact `Decimal` in a local context; floats
  rejected at every boundary. Known-value unit tests for all six calculators.
- **Timestamps:** `as_of` bounds SEC filing selection and the price window;
  freshness is derived from the last observation date vs retrieval. *Limitation:*
  the agent verifier does not enforce a v1-style "evidence-after-as-of" rejection
  (acceptable because market/SEC data is fetched up to `as_of`; noted in
  limitations).
- **Citation mapping:** citation indices are built from the answer's evidence
  order; every verified claim's cited evidence must resolve (validator-enforced).
- **Budgets:** enforced *before* every model/tool call; on exhaustion the loop
  stops and returns partial verified findings. Unit-tested per limit.
- **Replay:** reloads preserved claims/evidence/series and re-runs the verifier
  with no model/network; compares verdicts and values **numerically**. All
  demonstration and benchmark runs replay PASS.

## 8. Security — PASS (1 documented limitation)

- **Key handling:** read only via `get_secret_value()` to build the client; held
  as `SecretStr` (`repr=False`); `redacted()` masks it; never logged, persisted,
  committed, or returned to the client. `.env` is gitignored and never staged.
- **Secret exposure:** `/api/meta` and job results contain no key; errors use
  `error_code` + safe messages. Verified live (error card did not leak the key).
- **Dependencies:** `openai 3.57`, `fastapi 0.165`, `uvicorn 0.54`, `httpx 0.28`,
  `pydantic 2.13`, `starlette 1.10` — current; `pip check` clean; `web/` has a
  committed `package-lock.json`.
- **Prompt injection:** retrieved content is untrusted data (system prompt); tool
  outputs are truncated; the independent verifier makes injection unable to grant
  verification (test-covered). Attribution now requires a verbatim substring.
- **Path traversal:** `/api/runs/{run_id}` flows through `sanitize_run_id`
  (strict `RUN-YYYYMMDD-NNN` + containment); invalid ids → 404.
- **Local API access control — KNOWN LIMITATION (low):** the web API binds
  `127.0.0.1` with localhost-only CORS but has **no authentication**, so any local
  process or a page on any localhost origin could trigger research and spend the
  OpenAI budget. Acceptable for a local single-user MVP; do not expose the port.
  Tracked for v0.3.0 (optional shared-token like `strix.service`).

## Changes applied during the audit

1. **Hardening:** attribution verification now requires a verbatim substring
   (removed fuzzy keyword fallback). +2 tests.
2. **Fix:** replay compares values numerically (trailing-zero false-FAIL).
3. **Fix:** evidence-root guard tests tolerate populated docs. (both pre-audit)

## Unresolved defects

None release-blocking. Open items are feature gaps, tracked for v0.3.0:
- No FRED/BLS/Treasury connectors → economic questions return insufficient.
- No SEC financial-ratio calculators (e.g. operating margin) → such claims are
  unresolved rather than verified.
- Model non-determinism in tool breadth (e.g. sector coverage varies per run).
- Web API has no authentication (see §8).
