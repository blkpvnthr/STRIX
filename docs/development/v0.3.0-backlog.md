# STRIX v0.3.0 — Development Backlog

Focus: close the data and determinism gaps the v0.2.0 benchmark exposed, so answer
coverage rises while verification correctness stays absolute. No change to the
trust boundary — new data must flow through the same independent verifier.

## 1. FRED economic-data connector
- `connectors/economic.py`: FRED API (key via `FRED_API_KEY`), returning
  `ObservationSeries` for series like `CPIAUCSL`, `UNRATE`, `FEDFUNDS`.
- Wire `get_economic_series` to it; enable verifiable claims (e.g. latest CPI,
  YoY change) recomputed from preserved releases. Graceful unavailable without key.
- Acceptance: "latest US inflation rate" yields a VERIFIED claim with a primary
  FRED/BLS citation.

## 2. Treasury yield data
- US Treasury par-yield curve (Treasury `fiscaldata` / daily yield curve CSV; no
  key). Series per tenor (3M, 2Y, 10Y). Add a `yield_change` / spread calculation
  (e.g. 2s10s) to the verifier's calculator set.
- Acceptance: "how have Treasury yields recently changed" yields VERIFIED tenor
  changes.

## 3. SEC financial-ratio calculators
- Add ratio calculators to `strix.agent.calculations` + verifier recompute:
  operating margin, net margin, gross margin, revenue growth, margin change (pp) —
  reusing the exact-Decimal discipline of `analytics/profitability`.
- Acceptance: "how has Apple's operating margin changed" yields VERIFIED margin
  and margin-change claims (not unresolved).

## 4. Sector analytics
- A first-class sector universe (SPDR sector ETFs) and a `rank_relative_performance`
  helper so "which sectors are outperforming" deterministically fetches the set,
  computes relative performance vs SPY, and submits ranked VERIFIED claims.
- Acceptance: sector question is answered on every run, not model-dependent.

## 5. Deterministic research planner
- `planner.py`: map question intent → a fixed tool/calculation plan (which series
  to fetch, which calculations to run) before the model loop, removing per-run
  coverage variance. The model still proposes claims; the planner guarantees the
  evidence is gathered.
- Acceptance: repeated runs of the same question produce the same verified-claim
  set (coverage becomes reproducible).

## Supporting / hardening
- Optional shared-token auth for the web API (parity with `strix.service`); keep
  `127.0.0.1` default. Addresses the v0.2.0 local-access limitation.
- Point-in-time gate in the agent verifier (reject evidence known after `as_of`),
  matching v1's `EVIDENCE_AFTER_AS_OF`.
- Retrieve-and-preserve web source content so web-sourced attributed claims have
  inspectable excerpts (raising attribution coverage honestly).
- Pin runtime dependency versions for reproducible installs.
